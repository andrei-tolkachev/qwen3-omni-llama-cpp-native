# Qwen3-Omni для llama.cpp — True Full Duplex

Независимое расширение для **Qwen3-Omni-30B-A3B-Instruct**: Talker, Code Predictor и Code2Wav на GPU, смешанное квантование Talker в Q4, потоковые текст и PCM, отмена генерации и управление видеопамятью.

**Сам llama.cpp, его сервер и GGML созданы авторами апстрима.** Andrei Tolkachev принадлежат только собственные доработки Omni и исходные ядра, выпущенные под MIT. Исходные лицензии и авторство апстрима сохранены. Разработка выполнена с помощью AI. Это не официальный выпуск ggml-org или Qwen.

[Сборка и запуск](README.md#build) · [Подробная инструкция, веса и API](tools/loraai_omni_native/README.md) · [Лицензии](LICENSING.md).

Релиз содержит два архива: полное дерево исходников с Omni и небольшой комплект переноса доработок в новую версию llama.cpp. Внутри одинаковый нативный модуль; рядом публикуются SHA-256. Веса моделей не включены. Перед переносом выполните `scripts/apply_to_llama.py --check`, затем соберите весь согласованный набор бинарников и библиотек.

## Что добавлено в v0.2.0

Thinker обрабатывает новые текст, аудиофрагменты и изображения, пока Talker,
Code Predictor и Code2Wav продолжают синтезировать речь на GPU. Это параллельный
нативный инференс с отдельными рабочими потоками и состоянием моделей.

Запуск: `OMNI_DUPLEX=1 OMNI_MEMORY_MODE=resident`, затем открыть
`/v1/omni/duplex` с `{"adaptive_dialogue":true,"messages":[]}`. Входящие данные
и подтверждения воспроизведения отправляются отдельными HTTP-запросами.
[Полный протокол](tools/loraai_omni_native/DUPLEX.md).

- В адаптивном режиме в историю дописываются только завершённые фразы,
  подтверждённые проигрывателем. Уже услышанный текст не переписывается.
- При отмене отбрасывается неозвученное продолжение, а зависимый результат
  Thinker пересчитывается с согласованной историей.
- Работают ограничение очередей и опережения синтеза, резервирование VRAM,
  повторное использование точного KV-префикса Talker и подкачка весов.
  Точность моделей автоматически не снижается.
- Поддержаны дополнительные запросы Thinker во время речи, изображения,
  управление контекстом и точное озвучивание переданного текста.

Захват микрофона/камеры, воспроизведение, подавление эха и решения о том, когда
уступить слово или изменить ответ, реализует вызывающее приложение. В архиве
находятся нативные механизмы llama.cpp; готовая политика разговора не включена.

Для длинных ответов используется `stream:true,audio_protocol:2`: текст передаётся сразу по дельтам, звук — порциями PCM. Пример `scripts/voice_client.py` воспроизводит поток через ffplay; Ctrl-C останавливает проигрывание и отправляет отмену. Нарезка текста на фразы реализована в самом нативном модуле.

Измерения относятся к Linux/CUDA/RTX 5090. Выбор устройства не привязан к названию видеокарты, но другие устройства ещё не квалифицированы. Для одиночного запроса ранее проверен контекст 65 536. Дуплекс проверен на коротких входах при выделенном контексте 65K; почти полный контекст с одновременным мультимодальным вводом и 128K не подтверждены. Смешанный Q4 Talker выбирается автоматически, когда найден соответствующий файл. У BF16 известен случай зависания CUDA-умножения; Q4 проходит этот вход, но причина BF16-дефекта не устранена.

В длинном тесте получено 600,97 секунды сегментированного PCM. Отдельный непрерывный 12-минутный тест без нарезки завершился с неразборчивой речью. Длительность сама по себе не доказывает качество: проверены ASR на нескольких русских фразах и отдельных фрагментах; широкая проверка на слух, английский и другое оборудование отсутствуют.

Сервер отказывается слушать внешний адрес без ключа API. Ключ проверяется и для генерации, и для отмены. Для удалённого доступа используйте TLS. Исторические нативные результаты — в [VALIDATION.json](tools/loraai_omni_native/VALIDATION.json); проверки подготовки этого выпуска — в [RELEASE_VALIDATION.json](RELEASE_VALIDATION.json).

В разработке один последовательный запуск завершился CUDA Xid 11 на драйвере 595.99.02. Причина не установлена; исправление не заявлено. Последующие стрессовые и инструментированные проверки прошли. Измерения скорости и границы проверки — в [DUPLEX_VALIDATION.json](tools/loraai_omni_native/DUPLEX_VALIDATION.json) и [ADAPTIVE_DIALOGUE_VALIDATION.json](tools/loraai_omni_native/ADAPTIVE_DIALOGUE_VALIDATION.json).
